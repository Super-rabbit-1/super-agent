# 输入获取与证据边界

## GitHub 或代码仓库

1. 先读仓库说明、目录树、许可证、最近变更和测试入口。
2. 围绕用户想吸收的机制读取关键实现，不默认复制整个仓库。
3. 只有需要运行、搜索大量文件或验证行为时才克隆。
4. 区分项目提供的事实、作者主张和你从代码推断出的结论。
5. 记录仓库、ref/commit 和访问日期；不要把临时版本号写进长期规则。

## 网页、文章和技术文档

1. 优先读取原始来源；转载只用于发现原文。
2. 对可能更新的规范检查发布时间、版本和当前官方文档。
3. 需要登录的内部资源优先使用已有领域 CLI、连接器或授权会话。
4. 提取方法、约束、失败模式和验证方式，不把宣传文案当作能力。
5. 避免大段复制受版权保护的内容；沉淀自己的工作流和必要引用。

## 代码片段和本地文件

1. 识别语言、运行环境、入口、依赖、输入输出和错误处理。
2. 片段缺少调用上下文时，明确哪些结论只是推断。
3. 不运行来源不明的脚本，先审查依赖、网络、文件和命令副作用。
4. 不把示例中的密码、Token、内网地址或个人信息写入 Skill。

## 另一个 Skill

1. 完整读取对方的 `SKILL.md`。
2. 按其路由只加载相关 references、scripts 和 assets，但验证引用文件确实存在。
3. 比较触发范围、流程、工具、安全边界和输出合同。
4. 优先吸收缺失机制或改进现有 Skill；不要仅改名复制。
5. 保留来源和许可证信息，避免丢失必要归属。

## 获取完成标准

只有在能够回答以下问题时才进入深度分析：

- 来源是什么，当前版本或时间点是什么？
- 它实际解决什么问题？
- 核心机制在哪里得到证实？
- 哪些信息仍然缺失？
- 下一步分析是否需要执行代码或访问外部系统？
