# 消化决策准则

## 先过硬门槛

任一项为“否”，默认不创建新 Skill：

1. 是否能描述至少两个未来会再次出现的触发场景？
2. 是否包含模型无法仅靠通用知识稳定完成的流程、工具、边界或本地约定？
3. 是否能给出可执行的验证方法？
4. 核心内容是否在可预见时间内稳定，或具备更新机制？
5. 是否不存在覆盖率约 80% 以上的已有 Skill？

## 比较收益与成本

对每项按 0～2 分判断：

| 维度 | 0 | 1 | 2 |
|-|-|-|-|
| 重复频率 | 一次性 | 偶尔 | 高频 |
| 行动杠杆 | 只增加知识 | 改善判断 | 能稳定执行工作流 |
| 本地独特性 | 通用常识 | 有少量本地差异 | 强依赖本地工具/规范 |
| 稳定性 | 很快过期 | 部分稳定 | 核心长期稳定 |
| 可验证性 | 无法验证 | 人工判断 | 有命令、测试或明确结果 |
| 维护成本 | 高 | 中 | 低或可自动更新 |

不要机械按总分决策。前五项高而维护成本可控，才值得持久化；“有趣”不等于“值得吸收”。

## 选择承载形式

| 情况 | 推荐形式 |
|-|-|
| 当前问题的答案或临时资料 | 不持久化 |
| 一条跨任务、稳定、改变决策的原则 | 全局 `AGENTS.md` |
| 某仓库的命令、边界、验证和约定 | 项目或子目录 `AGENTS.md` |
| 某主题的一组细分行为规则 | 现有 rules 目录中的主题规则 |
| 已有 Skill 缺少一个场景、脚本或参考 | 扩展已有 Skill |
| 独立、多步骤、反复出现、可验证的流程 | 新建 Skill |
| 实时私有数据、授权动作或远端工具调用 | CLI、MCP、连接器或插件；Skill 只负责编排 |

## 80% 覆盖判断

比较候选能力与已有 Skill 的：

- 触发意图；
- 输入类型；
- 核心流程；
- 工具依赖；
- 安全边界；
- 输出合同；
- 验证方式。

七项中有六项基本一致，视为覆盖约 80% 以上。优先增量扩展，并检查 description 是否需要补充触发条件。

## 冲突处理

- 新来源与现有规则冲突：先找当前事实或权威来源，不直接覆盖。
- 全局规则与项目规则冲突：将项目差异留在项目层，不污染全局。
- 两个 Skill 触发重叠：合并或收窄 description，不让路由依赖猜测。
- 来源只提供结论、不提供机制：保留为当前参考，不写成长期规则。
